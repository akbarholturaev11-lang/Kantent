# Project memory — current architecture

This file is **not another policy document**. Keep only architecture, current technical state and hard-to-discover implementation constraints. For active behavior, read `AI_RULES.md` and the canonical sources in `AGENTS.md`. Delete superseded architecture notes when the implementation changes.

## Language architecture

`content/languages.json` selects default production languages and content roots; the calendar remains shared. `scripts/language-context.mjs` uses AsyncLocalStorage for isolated MCP language scopes and explicit child-process environments. `scripts/bilingual-production.mjs` collects separate results and reports partial/blocked outcomes truthfully. Default today/dated preparation and `content:make` use every configured production language.

The original series retains its file paths. Localized lesson/voice/CTA/Hook files are under `content/locales/tg/`; translated lesson JSON is bound to raw canonical source with `localization.sourceHash`. Translated CTA direction/rules are separately source-bound; histories are independent. The legacy CTA copy field name is retained for schema compatibility. Review packages use `review/<id>/tg/`; generated media uses `public/generated/tg/<id>/`, a sibling of original assets so invalidation cannot delete the other language. No profile, word timing or exact-preview approval is inherited across languages. Untagged historical publication evidence is interpreted as the original language, and calendar selection skips an episode only when all requested languages are published.

The new locale profile is a candidate: read its model-decision and sample/approval state from its configured JSON. Model authorization permits only the designated sample until owner audition/voice approval; successful sample generation records its language/model/profile identity. This is separate from publication approval and does not imply a connected translated-series social account.

## Components

- Local Node.js MCP server: `scripts/mcp-server.mjs`; clients are configured in `.codex/config.toml` and `.mcp.json`.
- Planning lives in `content/calendar.json` and `content/episodes/`. These are JSON files, not a database. The review copy is stored under `review/<episode-id>/`.
- Audio production: `scripts/generate-voice-gemini.mjs` sends approved narration exactly as written to Gemini TTS, converts WAV to MP3, gets word timestamps from Gemini Transcribe with the selected explanation language and Simplified Chinese hints, enforces exact normalized token alignment and imports through `scripts/import-voice.mjs`. Full-audio recognition can translate or omit Mandarin when its syllables are written in Cyrillic; `content/WORKFLOW.md` section 3 documents same-model language-specific segment recovery. `tokenParts` only maps the episode's verified Mandarin Hanzi syllables to its written phonetic tokens, so the exact normalized-token gate remains active. Gemini API requests have a 120-second timeout. A malformed word start is repaired only when its end and the prior word's end establish an adjacent boundary within 250 ms; otherwise the chunk is rejected. Only the designated pending sample can fall back to a prior sample after strict exact-text/model/voice/alignment validation. `content:make` and the MCP date workflow then render the Remotion package. The authoritative voice settings and approval state are in the selected content root’s `voice-profile.json`.
- Rendering: `src/EpisodeComposition.tsx` and `scripts/render-episode.mjs` using Remotion. `scripts/caption-utils.mjs` shares timing/phrase grouping between baked-in subtitles and exported SRT.
- `scripts/duration-policy.mjs` measures actual audio-aligned full-video frames and records whether the preferred `content/visual-system.json#duration` range was met before standard and TikTok review rendering. Duration outside the range does not block rendering; keep natural speech and the full CTA without padding, stretching or truncation. Approved/published historical dates are preserved.
- Visual numeric tokens come from `content/visual-system.json`; shot-level editing rules from `content/EDITING_SPEC.md`.
- Narrated motion-design working copies add per-scene `motionBeats`. `scripts/motion-design-plan.mjs` resolves them against verified Gemini captions, fails on ambiguous/missing/out-of-order cues, and writes `motion-timeline.json` through render preflight. `src/NarratedMotionScene.tsx` uses those frame anchors for contextual object/character actions and grammar graphics; legacy semantic/storyboard scenes and the central CTA keep their existing paths. CTA context hashing includes these optional plans only when present, preserving legacy registrations.
- `explain-actions-v1` reuses that exact-word resolver with structured `visual` and `explains` payloads. `scripts/action-design-plan.mjs` gates complete scene coverage and representable quantities/models; `src/NarratedActionScene.tsx` renders shared object/count/group, phrase, numeral, ordinal, comparison and choice components without lesson-specific IDs or text. The owner approved this presentation as the default; `content/visual-system.json#lessonPresentation` owns the active style/date. `scripts/lesson-presentation-policy.mjs` selects it for new drafts and rejects incomplete/legacy presentation before voice and both render paths. The AI author must write meaning-linked actions; the loader never fabricates them. The original reviewed example remains in `content/pilots/`. CTA context hashing binds these payloads through the existing motion-beat snapshot.
- New `graphic` beats carry declarative vector nodes and property keyframes in their `visual.graphic` payload. `scripts/graphic-scene.mjs` validates non-executable bounded drawings and samples deterministic transforms; `src/GraphicScene.tsx` draws them inside the existing action stage. The MCP editor exposes the same contract through `scripts/graphic-scene-schema.mjs`. New art/actions can be authored in episode data without extending the object enum. `lessonPresentation` owns the visible-state gate/date and maximum unchanged visual hold; the guard compares actual graphic payloads rather than planning text and render preflight measures holds against real word-cue intervals. This is structural QA, not automated aesthetic/semantic approval. See `content/GRAPHIC_SCENES.md`.
- The reusable action stage renders graphics only, with no authored headline or separate Hanzi/pinyin/meaning stack. `scripts/action-text-layout.mjs` selects the same cue-bound action for `CaptionOverlay`'s single subtitle block; verified Mandarin pinyin and necessary comparison examples stay inside that block. Original speech/cues and SRT remain complete. Phrase graphics can reuse an object/count explicitly authored elsewhere in the same scene. See `content/EDITING_SPEC.md` for the owner's presentation rule.
- Hook/CTA experiments, corrections and owner-entered analytics reside in their respective `content/*-lab.json` files; explanatory methodology is in the corresponding `*_LAB.md` files. `content/cta-lab.json#platformVariants` provides Instagram/TikTok/YouTube readiness; `scripts/platform-cta.mjs` builds safe platform-specific drafts. New planned source episodes contain *only* shared lesson scenes; `scripts/episode-cta-assembly.mjs` can attach a selected CTA ending, while the normal production loader currently defaults to Instagram. YouTube reuses Instagram's canonical CTA wording and voice/cues, replacing only the two profile/link screenshot assets. This is one shared lesson with a platform-specific ending, not separately generated lesson videos. `scripts/platform-exports.mjs` derives the approved YouTube ending from an already reviewed Instagram working copy, inheriting only its explicitly acknowledged current corrections and reusing an exactly matching immutable registration or appending a new baseline registration. `scripts/render-platform-videos.mjs` renders the lesson frames once, each muted CTA ending, and a continuous audio mix; bundled Remotion FFmpeg concatenates/muxes without re-encoding the shared frames. Normal make/render/MCP calls produce Instagram at the existing review root and YouTube under `review/<id>/youtube/`. `status.platformPackages` stores per-platform episode/content/CTA/media hashes; approval and publication records bind each target to its exact output. Edits invalidate both current exports while preserving approval/publication history. TikTok has an owner-approved manual-DM CTA with an effect-led review scene; `scripts/prepare-tiktok-review.mjs` registers the platform snapshot, voice/import scripts can target `--platform tiktok`, and `scripts/render-tiktok-review.mjs` writes a separate local package to `review/<id>/tiktok/`. TikTok publishing and automated DM delivery remain unauthorized. Immutable CTA registration metadata is reused only on an exact validation match; otherwise a new registration is required. Preserve historical snapshots rather than rewriting past experiment results.
- The publication integration uses the existing connected social MCP. `mcp-server.mjs` records the approved preview and returned post IDs/status under each episode's review package. `scripts/publication-policy.mjs` resolves per-target `scheduledFor` with legacy shared-time fallback; approval and result checks bind each account to its own approved instant. It does not store platform credentials or provide direct social-platform API authentication.
- Installed skills, functional categories and the lesson/premium/special stage-owner recipes live in `content/skill-catalog.json`. `content/SKILLS.md` explains the policy, and `scripts/skill-router.mjs` powers the MCP `recommend_skills` tool. Remotion remains the dated lesson renderer; a separate standalone premium/special project can use HyperFrames. HeroUI is a design reference only.

## Scenario authoring architecture

`scripts/graphic-voice-proof.mjs` renders an isolated technical drawing check using a language-scoped review's existing matching voice/cues. It records exact anchor frames and the original audio hash, preserves a complete boundary-crossing last word and stops before the next phrase. Diagnostic outputs remain separate from production episodes, platform exports and approvals; this helper never generates audio or rewrites the lesson.

`scripts/series-plan.mjs` proposes consecutive calendar parts read-only and validates complete numbered sets against `calendar.json#seriesPolicy`. The scenario buffer, consistency checker and production calendar readers share this validation; a missing remaining draft prevents counting that series as ready. Calendar metadata owns the relationship, while lesson/source identity and per-language publication approvals remain independent.

Scenario authoring remains with the Calendar Reserve agent for the future reserve and the invoking AI agent for manual draft requests; `content/WORKFLOW.md` owns the procedure. `scripts/storytelling-plan.mjs` reports authored topic choices and missing life-context/selection evidence without inferring a pattern from duration or question marks; it gives read-only structural advice and `scripts/storytelling-generator.mjs` contains pure source-bound brief/validation helpers. There is no Gemini text-author/critic module, model configuration or script-generation CLI. Approved Gemini TTS/transcription and the language-specific source/voice/CTA/review architecture remain independent of script authoring.

## Semantic visual connected review workflow

`scripts/auto-storyboard.mjs` calls `applySemanticReviewDraft` after creative format selection for eligible earlier CTA-free drafts outside the current presentation policy; new action lessons bypass this automatic semantic treatment. It records scene-specific `semanticShot` and rare unambiguous supported actions, not a universal student. Plans with prior voice or approval remain untouched. `scripts/semantic-visual-plan.mjs` compiles exact Gemini word-cue frames, and `scripts/render-episode.mjs` passes the plan through `scripts/render-platform-videos.mjs` into `src/EpisodeComposition.tsx` / `src/SemanticStoryScene.tsx` for legacy review MP4 exports. The timeline sidecar is re-created after invalidating older review artifacts. `scripts/platform-exports.mjs` checks the canonical `content/semantic-visual-system.json#productionEnabled` flag; verified platform exports/CTA/video hashes and exact owner-approved final previews remain mandatory. The standalone adviser/MCP preview remains read-only; see `content/WORKFLOW.md` and `content/SEMANTIC_SHOT_ADVISER.md`. Always verify true Gemini audio via owner video review; CI synthetic stills are not real-audio proof.

## Semantic visual foundation and owner-authorized production eligibility

`content/semantic-visual-system.json` owns allowed shot/action values and the owner-authorized production flag. `scripts/semantic-visual-plan.mjs` validates declarative action plans and binds them strictly to already imported Gemini word cues; `scripts/prepare-semantic-visual.mjs` writes a fingerprinted review-only visual timeline. `lib.mjs` and the MCP draft editor recognize additive semantic fields. `src/SemanticStoryScene.tsx` provides the P2 preview-only Remotion scene/actor/object renderer; it is wired through optional `semanticTimeline` in `src/EpisodeComposition.tsx`. `render-episode.mjs` now allows cue-verified semantic **review MP4** generation through the standard export path; **publishing** is eligible only with separate exact-owner-approved platform previews through the unchanged publication workflow. Old episodes and CTA continue unchanged. For full field semantics see `content/SEMANTIC_VISUAL_SCHEMA.md` and for the phased roadmap see `plans/SEMANTIC_VISUAL_STORYTELLING_PLAN.md`.

## Known implementation details

- The Tajik voice profile has an owner-approved model and sample; read voice identity and settings from `content/locales/tg/voice-profile.json`, preserve its approved sample audio hash and do not ask for the same audition again. Episode `er-vs-liang-cafe-20261026` has exact 143/143 same-model word timings, including the standalone Mandarin liǎng homophone recovered from its isolated clip. Its approved audio is about 69.9s. The 45–55s target is guidance only: render full speech/CTA at the natural audio duration without padding, stretching or truncating. Current Instagram and YouTube local review exports are under `review/er-vs-liang-cafe-20261026/tg/` and await owner approval; they are not published. Tajik imports follow the verified next-scene cue for the hook and allow an 8s ceiling so slower speech does not cut off the answer; Russian keeps its 6s cap.

- Voice labels in older episode snapshots can differ in spelling from the provider ID in `voice-profile.json`. `normalizeVoiceProvider` in `scripts/lib.mjs` handles legacy labels; do not modify historical snapshots solely to make their labels match.
- `Audio.trimAfter` uses an absolute source-frame endpoint. `scripts/import-voice.mjs` calculates it from the final timed word plus a natural pause; do not reinterpret it as a number of frames removed from the end.
- Gemini TTS and word-timestamp transcription are sent scene-aligned chunks of at most 12,000 narration characters per request, then joined into the episode's continuous audio track. This keeps total episode duration independent of Gemini's per-request token/audio limits.
- The original series’ Gemini profile has owner approval and remains fixed; read its identity from `content/voice-profile.json` and do not request per-episode reconfirmation. The cinematic sample's review package can still require its separate media review.
- Generated media and review data are intentionally ignored by Git; inspect local `review/<episode-id>/status.json` for actual render/publication state, rather than assuming that a source JSON marked planned means rendered/published.
- `scripts/scenario-buffer-plan.mjs` is a read-only calendar gap/date adviser. The AI agent, not this deterministic module, authors complete source-verified future episode JSON and updates the calendar directly on `main` under the owner-authorized Calendar Reserve workflow in `content/WORKFLOW.md`.
- Production scripts and the local MCP `prepareReviewForDate` entrypoint call `requireFreshGitMain` in `scripts/git-freshness.mjs`. It fetches GitHub `origin/main` AND the current remote source branch using regular Git, checks that neither remote has newer commits missing from local HEAD, fails closed when offline/stale/detached, and records the source revision in working status. It never auto-pulls or auto-merges.
- `scripts/self-improvement-check.mjs` audits the upcoming canonical scenario reserve read-only against `content/calendar.json#planningBuffer`.
- `scripts/feedback-analyzer.mjs` validates Git-versioned Zernio snapshots in `content/feedback/observations/` and computes source-based descriptive watch, skip, saves and shares. The first dataset contains real Instagram readbacks; post-to-episode mappings remain unknown. Neither a cloud scheduler nor an AI-driven rewrite engine is enabled.
- No trusted platform analytics ingestion is implemented: the labs store owner-provided results. No automatic cover-generation is established.
