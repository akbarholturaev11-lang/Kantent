# Project memory — current architecture

This file is **not another policy document**. Keep only architecture, current technical state and hard-to-discover implementation constraints. For active behavior, read `AI_RULES.md` and the canonical sources in `AGENTS.md`. Delete superseded architecture notes when the implementation changes.

## Components

- Local Node.js MCP server: `scripts/mcp-server.mjs`; clients are configured in `.codex/config.toml` and `.mcp.json`.
- Planning lives in `content/calendar.json` and `content/episodes/`. These are JSON files, not a database. The review copy is stored under `review/<episode-id>/`.
- Audio production: `scripts/generate-voice-gemini.mjs` sends approved narration exactly as written to Gemini TTS, converts WAV to MP3, gets word timestamps from Gemini Transcribe with Russian and Simplified Chinese language hints, enforces exact normalized token alignment and imports through `scripts/import-voice.mjs`. Full-audio recognition can translate or omit Mandarin when its syllables are written in Cyrillic; `content/WORKFLOW.md` section 3 documents same-model language-specific segment recovery. `tokenParts` only maps the episode's verified Mandarin Hanzi syllables to its written phonetic tokens, so the exact normalized-token gate remains active. Gemini API requests have a 120-second timeout. A malformed word start is repaired only when its end and the prior word's end establish an adjacent boundary within 250 ms; otherwise the chunk is rejected. Only the designated pending sample can fall back to a prior sample after strict exact-text/model/voice/alignment validation. `content:make` and the MCP date workflow then render the Remotion package. The **only authoritative production voice settings and approval state** are in `content/voice-profile.json`.
- Rendering: `src/EpisodeComposition.tsx` and `scripts/render-episode.mjs` using Remotion. `scripts/caption-utils.mjs` shares timing/phrase grouping between baked-in subtitles and exported SRT.
- Visual numeric tokens come from `content/visual-system.json`; shot-level editing rules from `content/EDITING_SPEC.md`.
- Hook/CTA experiments, corrections and owner-entered analytics reside in their respective `content/*-lab.json` files; explanatory methodology is in the corresponding `*_LAB.md` files. `content/cta-lab.json#platformVariants` provides Instagram/TikTok/YouTube readiness; `scripts/platform-cta.mjs` builds safe platform-specific drafts. New planned source episodes contain *only* shared lesson scenes; `scripts/episode-cta-assembly.mjs` can attach a selected CTA ending, while the normal production loader currently defaults to Instagram. YouTube reuses Instagram's canonical CTA wording and voice/cues, replacing only the two profile/link screenshot assets. This is one shared lesson with a platform-specific ending, not separately generated lesson videos. `scripts/platform-exports.mjs` derives the approved YouTube ending from an already reviewed Instagram working copy, inheriting only its explicitly acknowledged current corrections and reusing an exactly matching immutable registration or appending a new baseline registration. `scripts/render-platform-videos.mjs` renders the lesson frames once, each muted CTA ending, and a continuous audio mix; bundled Remotion FFmpeg concatenates/muxes without re-encoding the shared frames. Normal make/render/MCP calls produce Instagram at the existing review root and YouTube under `review/<id>/youtube/`. `status.platformPackages` stores per-platform episode/content/CTA/media hashes; approval and publication records bind each target to its exact output. Edits invalidate both current exports while preserving approval/publication history. TikTok has an owner-approved manual-DM CTA with an effect-led review scene; `scripts/prepare-tiktok-review.mjs` registers the platform snapshot, voice/import scripts can target `--platform tiktok`, and `scripts/render-tiktok-review.mjs` writes a separate local package to `review/<id>/tiktok/`. TikTok publishing and automated DM delivery remain unauthorized. Immutable CTA registration metadata is reused only on an exact validation match; otherwise a new registration is required. Preserve historical snapshots rather than rewriting past experiment results.
- The publication integration uses the existing connected social MCP. `mcp-server.mjs` records the approved preview and returned post IDs/status under each episode's review package. It does not store platform credentials or provide direct social-platform API authentication.
- Installed skills, functional categories and the lesson/premium/special stage-owner recipes live in `content/skill-catalog.json`. `content/SKILLS.md` explains the policy, and `scripts/skill-router.mjs` powers the MCP `recommend_skills` tool. Remotion remains the dated lesson renderer; a separate standalone premium/special project can use HyperFrames. HeroUI is a design reference only.

## Known implementation details

- Voice labels in older episode snapshots can differ in spelling from the provider ID in `voice-profile.json`. `normalizeVoiceProvider` in `scripts/lib.mjs` handles legacy labels; do not modify historical snapshots solely to make their labels match.
- `Audio.trimAfter` uses an absolute source-frame endpoint. `scripts/import-voice.mjs` calculates it from the final timed word plus a natural pause; do not reinterpret it as a number of frames removed from the end.
- Gemini TTS and word-timestamp transcription are sent scene-aligned chunks of at most 12,000 narration characters per request, then joined into the episode's continuous audio track. This keeps total episode duration independent of Gemini's per-request token/audio limits.
- The currently configured Gemini voice profile has owner approval and serves as the fixed series voice; read its identity from `content/voice-profile.json` and do not request per-episode reconfirmation. The cinematic sample's review package can still require its separate media review.
- Generated media and review data are intentionally ignored by Git; inspect local `review/<episode-id>/status.json` for actual render/publication state, rather than assuming that a source JSON marked planned means rendered/published.
- `scripts/scenario-buffer-plan.mjs` is a read-only calendar gap/date adviser. The AI agent, not this deterministic module, authors complete source-verified future episode JSON and updates the calendar directly on `main` under the owner-authorized Calendar Reserve workflow in `content/WORKFLOW.md`.
- Production scripts and the local MCP `prepareReviewForDate` entrypoint call `requireFreshGitMain` in `scripts/git-freshness.mjs`. It fetches GitHub `origin/main` AND the current remote source branch using regular Git, checks that neither remote has newer commits missing from local HEAD, fails closed when offline/stale/detached, and records the source revision in working status. It never auto-pulls or auto-merges.
- `scripts/self-improvement-check.mjs` audits the upcoming canonical scenario reserve read-only against `content/calendar.json#planningBuffer`.
- `scripts/feedback-analyzer.mjs` validates Git-versioned Zernio snapshots in `content/feedback/observations/` and computes source-based descriptive watch, skip, saves and shares. The first dataset contains real Instagram readbacks; post-to-episode mappings remain unknown. Neither a cloud scheduler nor an AI-driven rewrite engine is enabled.
- No trusted platform analytics ingestion is implemented: the labs store owner-provided results. No automatic cover-generation is established.
