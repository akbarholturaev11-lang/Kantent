# HSK AI Content — feedback agent playbook

This runbook is for ChatGPT using its already-connected **Zernio and GitHub** tools. It is not a background daemon. It requires no additional API key and collects no HSK AI application user data.

## GitHub connector writes for scheduled Feedback (owner migration 2026-11-09)

**Owner instruction 2026-11-09 supersedes the 2026-10-14 feedback branch/PR requirement.** This scheduled Feedback agent writes verified, append-only analytics **directly to current `main`**, without a topic branch, PR or PR-CI wait. This is a narrow exception for **new files under `content/feedback/observations/` and `content/feedback/reports/` only**. No script, locale, calendar, Hook/CTA policy, voice, renderer, publishing, DM or other repository file may be modified by Feedback. Calendar Reserve's distinct direct-main source-drafting authority remains governed by `content/WORKFLOW.md`.

1. Before writing: confirm actual Zernio connections and fresh provider evidence; read current `main` SHA, canonical rules, existing observations/reports and pending feedback PRs. Reconcile earlier PR-only reports without duplicating their snapshots. A repeated provider snapshot is a **no-op**.
2. Validate provenance, exact window evidence, IDs, schema, units, unknown/null semantics, and the proposed report. Run available read-only consistency checks if executable. If validation or source access is insufficient, **skip the write** and report the blocker.
3. Use the connected GitHub connector `create_file` on **`main`** for each new append-only observation/report. If a same-date file already exists, never overwrite it: compare evidence and either skip the duplicate or create a distinct dated+collection-timestamp path for genuinely new measurements. `update_file` is permitted only for a necessary, explicitly reconciled correction to an existing feedback report, using the latest fetched blob SHA; never rewrite prior raw observations. Fetch the fresh `main` HEAD immediately before writes; if another agent moves it, re-read affected paths and reconcile before continuing. Never force push.
4. After each write, fetch the file back from `main` and verify its bytes, source IDs and metadata. Fetch final `main` HEAD and all new files again. Check the actual GitHub Actions runs associated with the resulting `main` commit, including failures or pending checks; direct writes cannot wait for PR CI, so **never claim CI passed before it actually completes**. Report any regression explicitly and do not perform unrelated repairs under this agent.
5. Report exact paths, final `main` SHA, provenance/window/confidence, duplicate/skipped counts, CI status and remaining gaps. If GitHub denies writes, stop and report the failure; do not fall back to a branch/PR unless the owner changes this policy. This authorization does not imply approval for video or social publishing.

## Skill boundary for the Monday/Wednesday/Friday scheduled run

At the start of each run, read the latest `main` canonical catalog and `content/SKILLS.md`. The agent's main job is **owned video-account feedback** using current Zernio connections and real post data from the language-matched Instagram, YouTube, TikTok and Facebook destinations; Telegram is a **separate factual Tajik product-news text + original 4:3 image** channel (owner-authorized automatic publication via `content/telegram-agent.json`) and remains outside VIDEO analytics. The Feedback agent does not publish anything.

- For analysis of existing *owned* posts, apply `content/hook-lab.json`, `content/feedback/` and the current analyzer. Do not misroute owned analytics to `ig-competitor-research`, which is explicitly for independently sourced competitor observations.
- If the agent has directly supplied/authorized external competitor Reels with independently verifiable measurements, use `.agents/skills/ig-competitor-research/SKILL.md` to write **optional read-only hypotheses** in a clearly separate research section. No observed competitor data is pasted as HSK AI results or counted in Hook Lab.
- When proposing a new Instagram publication caption to the owner (not when measuring historical post metrics), apply `.agents/skills/ig-caption-quality/SKILL.md`. Keep such proposed copy separate from canonical CTA and never silently mutate published packages or episodes.
- `ig-reel-planning` is for **new lesson editorial drafts** during Calendar Reserve, not the analytics run; do not author new scripts as a side effect of this job. If the evidence suggests a test, report a proposed hypothesis for a future separately authorized lesson.

## Analysis run (external ChatGPT schedule: Monday / Wednesday / Friday, Asia/Shanghai)

1. Fetch the latest GitHub `main` SHA and read the **current** `hsk-tu-vous/AGENTS.md`, `AI_RULES.md`, `content/calendar.json`, `content/hook-lab.json`, `content/cta-lab.json` and this playbook. Check all pending feedback PRs plus current `main` observation/report files first. Avoid repeated or missing historical report snapshots.
2. **First call connected Zernio `accounts_list` and verify current account IDs/platforms against `content/publication-destinations.json`; never assume an account is connected because old Zernio posts mention it.** Collect only real posts for currently connected language-matched video destinations. Historical account reports are not current-account guarantees; do not treat old TikTok or Facebook post IDs as proof of a present connection. Telegram is a non-video Tajik news+4:3 image destination under a different agent, and is excluded from this VIDEO account analysis. Read horizon and windows ONLY from `content/hook-lab.json#policy` (rolling 30 days by actual `publishedAt`; `24h` early signal; `7d` primary). Preserve actual platform post ID, URL, timestamps, metric units, source/provider refresh times and account ID. If platform/provider history coverage is less than 30 days, report the coverage gap. Missing/unavailable or unsupported provider metrics are unknown/null, never assumed zero.
3. Add append-only, provenance-stamped **separate per-platform** snapshots in `content/feedback/observations/` following the README and schema; never overwrite old measurements or silently replace them with fresh cumulative values. Create a dated report covering each connected video destination with usable data and link the actual evidence files. For cumulative Zernio totals use `window: "lifetime"`, not fabricated exact 24h/7d windows; a provider daily cumulative timeline does not automatically certify exact elapsed-post-age windows.
4. Match source `episodeId` / hook format / HSK level / effect style only if the published media and existing episode source prove the mapping. Unverified fields remain `null`.
5. Inspect the read-only `content:feedback`, `content:viral-plan`, `content:buffer` and `content:variety -- --results` reports (the last joins each illustrated lesson's recorded visual-variety A/B arm from `content/lesson-art/*.json#variety` with fixed-age 7d observations; report its per-arm sample and decision, which stays `insufficient-evidence` below `content/visual-variety.json` `minimumPerArm` — promoting an arm is an owner decision). For a new cycle create a dated feedback report containing OBSERVATION, HYPOTHESIS, EXPERIMENT and DECISION sections, plus source links and uncertainty. Only source-verified `24h` may provide an early signal; only source-verified `7d` within the rolling 30-day publication cohort may support a primary recommendation. Require verified episode-to-post mapping, matched platform, same window, level, duration band, minimum comparable post sample and views. No lifetime/72h substitution. Never infer a 24h or 7d result simply by waiting 24h or 7d before fetching cumulative lifetime.
6. If calendar/read-only diagnostics show a missing or incomplete future scenario reserve, record the concrete dates/IDs, per-language gaps, and which of the **configured languages** remain source-incomplete. **Do not write or repair any episode, translated lesson, motion graphic or calendar row in a Feedback run.** Hand the factual shortfall to the separately scheduled Calendar Reserve agent under `content/WORKFLOW.md`; no automatic cross-agent run is implied. This analytic task's GitHub PR must contain only feedback observations and reports.
7. Report each content type against its own goal from `content/creative-formats.json#contentGoals` (lessons: link requests/sign-ups; advertisements: reach and watch to the brand ending; serial parts: follows, else part-to-part continuation). Record `metrics.follows` only when the provider reports follows from that post. **Do not modify scripts, future plans or creative policy as a feedback side effect.** For an eligible primary fixed-age `7d` cohort with verified post-to-episode/hook/HSK/format provenance, calculate descriptive matched comparisons and document the Hook Lab sample/lift/secondary-metric criteria; these are still not proof of causality. Record a proposed future experiment and seek separate owner approval/authoring authority before any production rule change. If data are lifetime-only or unlinked, mark `insufficient-evidence`. Never modify CTA wording, voice, approved/published snapshots, render code, calendar or social publication.
8. Write verified append-only feedback files directly to current `main` under the narrowly scoped authorization above; inspect actual post-write CI and disclose failures or pending checks. Finally fetch all reported file paths from `main` and verify its commit SHA, and summarize metrics by platform/account, provenance gaps, exact changed files, PR, merge commit, CI conclusion and whether main contains every file. Never claim unattended execution unless the scheduled task actually confirmed it.

## Production handoff only (not a Feedback-agent action)

When a separately owner-invoked **video production agent** prepares media, that agent re-reads the current `main`, matching episode, language-specific Hook/CTA Lab and voice/visual rules and captures the source SHA. Changed sources invalidate stale previews and require fresh review under `content/WORKFLOW.md`. **The Feedback agent must not start production, generate voice, alter reviews or invalidate media during an analytics run.**

## Storytelling pattern evidence

For adaptive script comparisons, an optional observation `storytellingPattern` can be `direct`, `single-rehook` or `layered` only **after** proving the published media corresponds to the exact episode/narration story version and verified Hook, HSK level and creative format. Save that provenance with source records, not guesses based on thumbnail or lesson topic. Missing mappings remain `null`, not defaulted to direct. `feedback-analyzer.mjs` separates eligible fixed-age 7d observations by verified pattern, platform, level, duration band, Hook **and** `creativeFormatId` (with an explicit unverified bucket), but does **not** by itself prove a causal lift, secondary guardrails or a winner; it never treats provider lifetime metrics as fixed post-age observations. Owner sign-off remains necessary before any learned policy is promoted.

## Non-goals

No customer-install attribution, no separate social API token, no user data extraction, no causal claim from views alone, no automatic winner declaration, no autonomous publishing. Existing owner approval of the exact final preview remains mandatory.

## All-content ownership update

Apply `CONTENT_TRACKING.md` to ordinary lessons, ads and serial parts in every default language. Zernio operations preserve the approved calendar part/date and exact language/platform preview; Feedback validates mappings and analyzes separated cohorts, then proposes tests for Calendar Reserve. Feedback never writes source scripts or calendar rows. Recurring tasks must read current `main` and these canonical runbooks on every run; updating repository instructions does not itself change an external task schedule.
