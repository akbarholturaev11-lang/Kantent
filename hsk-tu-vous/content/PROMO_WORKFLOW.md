# Standalone HSK AI advertisements

The owner selected situation-led advertising and a minimalist visual treatment from an uploaded reference. The canonical story policy and reference audit live in `creative-formats.json#promoPolicy`; visual limits, backgrounds and direction live in `visual-system.json#promoPresentation`. This procedure applies to newly authored, unapproved commercials. Preserve existing approved promo briefs, media and publication history.

## Author the story and frame plan

1. Ordinary ad requests cover every `defaultProductionLanguages` entry in `languages.json`, just like ordinary lesson production. An explicit language request narrows that set. Resolve platforms from the owner's request, then read each selected language's own voice profile and CTA Lab. The invoking AI agent writes ads; Calendar Reserve's dated-lesson authority is not an ad scheduler. Gemini remains the approved voice/transcription provider after writing.
2. Pick one recognisable life task and one source-supported HSK AI benefit. Describe the setting, learner goal and friction. Select a compatible story format from the promo policy. Start with the situation; develop the specific difficulty, demonstrate the useful product action, then resolve the task. Scene count follows the story. Advertising is separate from the lesson-only Direct / Single Re-hook / Layered contract and its teaching-answer timing.
3. Treat a fictional scene as an imagined example in the actual opening narration. Use a true first-person anecdote/testimonial only with documented owner-provided source evidence. Do not import the reference's security story, features, dialogue or branding into HSK AI. Avoid invented real students, fear claims, statistics, proficiency gains or guaranteed results.
4. Save the shared CTA-free draft to `content/promos/<promo-id>.json` and complete versions under each selected language's configured `<contentRoot>/promos/<promo-id>.json`, keeping the same ID. Use the paired `speaking-cafe-example.json` records as schema illustrations, not approved scripts. Required fields are `schemaVersion`, `kind:advertisement`, `status:draft`, `id`, `language`, matching `languageCode`, `styleId`, `formatId`, `benefit`, `situation:{setting,learnerGoal,friction}`, `storyType`, `evidence`, `claims` and `beats`. An illustrative story includes `storyDisclosure` verbatim in its first narration; a documented one references a `storySourceId` receipt. A translation also carries `localization:{language,sourcePromoId,sourceHash,authoredOn,status:draft}`. `sourceHash` is `promoSourceHash` (SHA-256 of `JSON.stringify` on the raw shared source). Any shared-source change requires localization review and a fresh binding.
5. Evidence receipts are `{id,kind,sourcePath,checkedAt,supports}`: use `product-source` for capabilities and a separate `personal-story` receipt for a documented experience. Claims are `{id,text,evidenceIds}`; claim text must appear verbatim in narration and bind to product-source receipts. Open the actual current sources and independently verify meaning, applicability and privacy. A file-existence or JSON check cannot establish that a claim is true. Preserve source UI language, crop irrelevant/private fields and disclose any mismatch as work still required; never repaint a capture as a different language or simulate a new AI response.
6. Each beat is `{id,role,narration,visual,claimIds?}`. The first role is `situation`; include a `product-demo` and finish with `resolution`. Other roles come from the promo policy; do not force a fixed number. The visual names one `focalSubject`, a concrete `action`, `continuityKey`, exact spoken `cueText` and a canonical `backgroundToken`. Original illustrations use `type:illustration` and a `drawingBrief`; genuine product views use `type:product-capture`, `assetPath`, `provenance:genuine-product-capture` and supported `claimIds`. Optional `limitations` are outstanding production work. Paths are relative to this project, remain within the repository and refer to actual files.

## Build the minimalist video

Keep one dominant object/action and one narration caption, as defined by the visual policy. No additional headline repeating the subtitle or unrelated text stack. Product UI text can remain inside the genuine capture; crop and focus it for phone readability. Use an original character, hand, cup, phone or other relevant object; preserve its identity and continuity when moving between scenes. A product view replaces that focal object at the relevant phrase. The background and restrained accent follow meaning, rather than cycling by time. Build depth with original simple geometry, cutout-like framing and gentle camera changes when useful.

Before media work run `npm run content:promo-plan -- <promo-id>` or `get_promo_plan`; both default to every configured production language. Use CLI `--language tg` / MCP `language:tg` only for an explicit narrowed request. The report has per-language variants and `plansComplete`; missing, stale or malformed translations produce `partial`/`blocked` and a failing CLI status, never a source-language substitute. A plan pass is not a completed media package. This is a read-only structural/evidence-path gate. Its `requiredBeforeMedia` lists remain work to complete; a prose `drawingBrief` is not an illustration. Build missing artwork and inspect its poses first. Remotion can reuse the safe declarative drawing contract in `GRAPHIC_SCENES.md`; a standalone HyperFrames project follows its selected workflow. Existing engines stay in place under `SKILLS.md`; the style choice does not migrate a project.

Keep the same supported benefit, story/claim IDs, beat roles and order, and verified Chinese examples across languages. Translate all explanation text, disclosures, claims and exact visual cue words for the selected audience; never leave copied source narration in a localized beat. Geometry and genuine captures may be shared when their meaning is unchanged. Select a capture with the correct interface language, or declare the mismatch as outstanding work; the example includes an actual Tajik UI capture. Product capabilities and the underlying receipts remain the same.

For every selected language, carry its validated story into a separate project `BRIEF.md` / storyboard or language-scoped composition props. Review each story-to-frame mapping before speech. Append that language's current central platform CTA only during production, then generate its full matching narration with its own approved profile. Resolve changes against that language's real imported word timings; no invented milliseconds, copied foreign-language timing or fixed equal scene divisions. Keep output namespaces separate under `review/promos/<id>/<language>/` and `public/generated/promos/<id>/<language>/` (the planner reports these paths but writes no media). Never copy another language's voice, captions, approval or publication result. Report each blocked/partial version accurately; do not call the whole requested set complete until every required media package passes QA. For every spoken object/action, inspect the actual corresponding frame, its movement and its transition in the final MP4. A static screenshot may show existing UI, but must not claim to be a newly recorded live interaction. Show an actual recording when the narrated benefit requires seeing a response/change.

Duration follows the complete natural narration and central CTA; the shared preferred range is guidance. Validate the complete encoded video, audio, captions, current product evidence, missing assets and phone readability before reporting a review package ready. The planner never creates voice, drawings, MP4s, approvals or social schedules. Publishing still requires the exact language/platform preview, accounts, copy, settings and time approved under `AI_RULES.md` / `WORKFLOW.md`.
