# HSK AI video production — operating procedure

This file describes **the sequence of operations**, not the values of production settings. Start with `AGENTS.md` and `AI_RULES.md`. Read current values from the canonical files listed in `AGENTS.md`; never substitute remembered dates, voice profiles or CTA wording.

For a new standalone advertisement, enter `content/PROMO_WORKFLOW.md` before authoring. `recommend_skills` returns those advertising references as `creativeGuidance`, and `get_promo_plan` / `content:promo-plan` validates its original story and frame plan read-only. The calendar selects the required production path by content type; Calendar Reserve drafts the typed future source reserve described below.

## Runbook: «Бугунги видеони тайёрла» / "prepare today's video" (Codex)

The short path for the owner's daily command. Each line names the stage the tool returns and the section that owns the details; it adds no rule of its own.

0. **Start right.** Work in `hsk-tu-vous/` (its `.codex/config.toml` starts the project MCP server) on a checkout whose `HEAD` contains the latest remote `main`; production refuses a stale checkout. Run `npm ci` when `package-lock.json` changed, then `npm run check:consistency`. Call `recommend_skills`; a lesson stays on Remotion.
1. **Call `prepare_today_video`** (CLI: `npm run content:make -- today`). Act on the returned stage, then call it again:
   - `authoring-required` — the calendar has nothing for today or later: author today's `weeklySchedule` slot (§1.3).
   - `action-plan-required` — complete every beat's cue-linked `motionBeats` with `visual.illustration` (§2.4, `EPISODE_SCHEMA.md`) and register the changed CTA context.
   - `lesson-art-required` — the Codex frame task (§2.6): generate the missing frames named in `review/<id>/lesson-art-codex-brief.md`, record them, pass `npm run content:art:review -- <id>` and confirm each frame visually.
   - voice runs by itself (one take per language, §3); a blocked STT keeps the paid audio — diagnose and resume, never buy a second take unasked.
   - `partial` — fix the named language/platform and call again.
   - `ready-for-review` — continue with step 2.
2. **QA the real MP4s** (§4.3, `EDITING_SPEC.md#review-before-delivery`): watch each with sound and check cue frames at 270×480 — the frame matches the spoken word, only the HSK AI cast appears, no face is covered, headline/chip/subtitle never repeat each other, all text stays in the safe band.
3. **One grouped preview** of every RU/TJ × Instagram/YouTube/TikTok/Facebook package with a Zernio-based time per account (§5.1–5.3). Wait for the owner's explicit approval; nothing is uploaded or scheduled before it.
4. **Publish only the approved targets** through the route in §5 and record each receipt.

Never in this flow: publish without approval, regenerate a good voice take or a saved frame, use the paid image API (`--paid`) without the owner's request, draw or invent a character, select a past date, or rotate keys on HTTP 429.

## 3. Generate and import speech

1. Read the current provider, model, voice and approval status from the selected language’s `voice-profile.json`. Check `modelDecisionRequired` first; it requires the exact owner model decision before any sample API call. While a profile is `pending-owner-approval`, generate only the sample episode named there; wait for the owner to approve that sample before using it for other episodes.
2. Run `npm run content:voice -- <episode-ID>` or `content:make`. Default transport remains OpenRouter; to use Gemini Direct as primary set `HSK_AI_VOICE_API_PROVIDER=gemini-direct` and `HSK_AI_ALLOW_GEMINI_API=true`. An **optional** explicitly enabled OpenRouter backup (`HSK_AI_OPENROUTER_FALLBACK_ENABLED=true`, valid `OPENROUTER_API_KEY`, account spend cap, tested voice) may handle Direct HTTP 429, transient HTTP 5xx or Google's HTTP 400 region refusal (“User location is not supported”). Google quota errors do **not** rotate between Google project keys. The default is one TTS take of the whole narration per language/package (owner decision 2026-11-08, see `AI_RULES.md`); `HSK_AI_TTS_MODE=scene` restores per-scene takes on explicit request. Do not mix new OpenRouter TTS with already completed Direct audio; block and preserve chunks if a later chunk fails. A fallback on STT must reuse saved WAV/MP3, never regenerate speech. Preserve requested/actual transport in resumable metadata and require exact word timestamps. Direct Gemini may receive RU/TG+Mandarin hints; OpenRouter receives one ISO-639-1 hint per request (without it a real Tajik window came back as 6 words with inverted times). Do not claim a genuine voice QA pass from synthetic CI.
3. The generator compares the normalized word sequence against the complete narration. It imports MP3 and VTT automatically only when every word matches and all timestamps are valid. A match is position-by-position; the only accepted spellings of the same spoken word are Tajik ӣ/и and ӯ/у (as Russian ё/е), a word the recognizer split into 2–3 parts that concatenate exactly to it, one recognized word that is the exact join of 2–3 written locale words (“тоже” for “то же”; the covered words share its measured span), a one-letter Latin formula variable heard as its homoglyph or letter name (“А”/“би” for “A”/“B”), and a Hanzi written in Cyrillic, toneless pinyin or the Latin letter whose Chinese name is that syllable (“B” for 比) when an author-verified `hanzi`/`pinyin` pair in this lesson or another repository lesson gives that reading (character and syllable counts must agree; nothing is guessed). Captions always display the source narration. Before a new STT attempt on a resumed take, its already saved responses are re-checked against the current gate. Audio of 25 s or more (every one-take) is transcribed in contiguous windows of at most 22 s cut only at measured silences (`scripts/stt-windows.mjs`; ffmpeg silencedetect −35 dB/0.25 s); provider timestamps are offset by each window's exact start, and no window boundary is placed inside speech (without a measured silence the whole file stays one request). Every paid window/pass/clip response is saved with its exact bounds and hints and is reused by later attempts and resumed runs instead of being bought again. Gemini Transcribe's free tier allows about **3 requests per minute and 25 per day** per project, so a take must not spend requests on identical retries: a windowed take gets two attempts per run (the second only re-requests failed windows), a short scene chunk three, all on the same saved audio (a resumed take is never left with zero); after three mismatched attempts in a run, only the designated pending sample may reuse a prior sample whose exact narration, Gemini voice/model and timestamp alignment all validate; both the rejected attempt and fallback provenance are retained in metadata. For other episodes, a mismatch keeps generated files and diagnostics under `review/<episode-id>/gemini-production/<timestamp>/` and blocks rendering. Diagnose the specific mismatch before retrying; never regenerate or replace an owner-approved audio file to work around transcription.
   - `content:make` prepares TikTok's approved manual-DM variant separately with `--platform tiktok`, so its narration, audio and word cues stay in `review/<id>/tiktok/`; do not replace the existing root review episode or its other exports.
4. If a mixed explanation-language/Mandarin full-audio pass translates or omits spoken Mandarin syllables, recover captions from the saved audio using the same Gemini Transcribe model and provider: (0) on the direct transport, transcribe only the STT windows that still contain a gap, once per single language hint that is missing there (explanation language and/or Mandarin), and let the strict selection take one time-ordered exact cover from all passes, because a mixed-hint pass can drop either language (the real RU one-take dropped every Mandarin sentence); only remaining gaps go to clips, at most 8 per window; (a) keep the normal full-audio pass with the locale from the selected language’s `voice-profile.json` and the Simplified Chinese hint; (b) isolate only the audible Mandarin spans and transcribe those clips with the Simplified Chinese hint, requesting verbatim word timestamps; (b′) a gap that interleaves explanation-language and Mandarin words with no verified inner boundary is transcribed once per single hint on Direct (once without hint on OpenRouter); (c) isolate spoken Latin acronyms such as “HSK AI” and transcribe those clips with the locale from the selected language’s `voice-profile.json`; (d) save the original pass responses and each source clip's start/end offsets beside the saved generation; (e) convert each clip timestamp back to the source timeline, merge annotations in time order with the explanation-language pass, and map Hanzi to the episode's written phonetic token only when the character and spoken syllable are verified. Do not estimate missing timestamps or write VTT unless the existing exact normalized-token check and timestamp validation both pass. Then rerun `content:make` or `npm run content:voice -- <episode-ID>`: a SHA-verified saved take of the same narration/profile/transport/mode resumes automatically, synthesizing only missing chunks (`--resume <timestamp-folder>` names one explicitly). If an older paid take of the same narration exists that cannot resume automatically (no recorded SHA-256, another transport or chunk plan, or an imported take the working copy no longer references), generation stops before any TTS request and lists it; listen first, then re-import it, resume it explicitly, or buy a new take only on an explicit owner decision with `--new-take` (MCP `forceNewTake`), which also retires every older take of that narration. Do not change the approved voice, provider or audio.
5. The importer verifies the narration fingerprint, cue granularity, cue bounds, eligible voice profile (approved profile or its designated pending sample) and publication state. It maps timed cues to scenes, records the generated audio in `public/generated/`, and removes trailing silence only after the final timed word. Record the complete natural video duration against `content/visual-system.json#duration` as guidance; the 50-second target is a pacing reference only, with no minimum or fixed maximum. Keep useful narration and the complete CTA, and never pad silence, stretch audio or truncate speech to reach a target.
6. The configured Gemini-model API transport processes narration/audio: OpenRouter by default, or direct Gemini only with explicit opt-in. Direct Gemini uploaded audio must be deleted after transcription; OpenRouter inlines its audio rather than creating a Gemini uploaded file. Keep API keys only in protected secrets or `.env.local`, never logs/source. The first RU/TG TTS attempt should meet voice quality and Mandarin pronunciation criteria; the one-take default was chosen from a genuine owner-listened A/B (RU 57.0 s vs 62.6 s scene-wise, TG 60.4 s vs 67.9 s, fewer long pauses and signal jumps). On STT failure, resume from preserved WAV, not a fresh paid TTS request. An OpenRouter TTS HTTP 429/5xx error response (no audio) is retried once, honoring Retry-After up to 30 s; a timeout or network abort is never retried automatically because audio may already have been billed. Every TTS chunk's signal (peak, RMS, longest pause, clipping, near-silence) is recorded before STT; digital silence or ≥98% near-silent audio stops the run with the WAV preserved and no STT spent.
