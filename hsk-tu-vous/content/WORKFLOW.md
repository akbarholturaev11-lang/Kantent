# HSK AI video production — operating procedure

This file describes **the sequence of operations**, not the values of production settings. Start with `AGENTS.md` and `AI_RULES.md`. Read current values from the canonical files listed in `AGENTS.md`; never substitute remembered dates, voice profiles or CTA wording.

## Language-scoped production contract

Read `content/languages.json` for the default production language set and content roots. Both `prepare_today_video` and `prepare_video_for_date`, plus `content:make -- today|YYYY-MM-DD|episode-ID`, prepare every default language for the same calendar lesson. Production accepts `language all|ru|tg` (CLI `--language`); all other MCP operations accept `language ru|tg`, defaulting to the original series. Individual CLI stages inherit `HSK_CONTENT_LANGUAGE`. Always carry the selected language through planning, CTA registration, voice, render, status and approval.

The calendar and Chinese lesson identity are shared. Author complete localized CTA-free scripts with `localization.sourceHash` bound to the canonical raw lesson; changes to that lesson invalidate its translation. Never silently translate at render time, fall back to another language, or reuse another language's voice/timing. The agent must author missing/stale translation and meaning-linked action cues, register the locale CTA context, then retry preparation. Use the selected content root's voice/CTA/Hook files; keep measured histories independent. The translated CTA is source-bound to the shared direction/rules and requires re-review when those change.

Original review files stay at `review/<id>/`; translated files live at `review/<id>/tg/`. Each root has its own Instagram package, `youtube/`, status and exact-preview approvals. Generated original media stays in `public/generated/<id>/`; translated media uses the sibling `public/generated/tg/<id>/`, so invalidating one cannot delete the other. `languages-status.json` records the CLI aggregate. Return `partial` or `blocked` with per-language reasons when a language is incomplete; never claim both videos exist from planning/tests alone.

A candidate profile with `modelDecisionRequired` cannot call the API. Present its exact model and capability reason, then record only the owner's explicit decision through `approve_voice_model_for_sample`. That permits the designated sample, not series approval. Successful sample generation stores its MP3/VTT and identity metadata in that language's profile. After the owner listens, `approve_voice_profile` approves only that language. Do not request repeated approval of the original series' already approved profile. No publication is authorized by either voice decision.

The actual review MP4 uses `SemanticStoryScene`. Synthetic CI still frames do not prove real Gemini narration quality: owner must inspect the real MP4/audio. No automatic Zernio post occurs.

Previously generated, voiced, reviewed, approved and published episodes are NOT automatically rewritten or replaced. ## Automatic creative storyboard for upcoming videos

The command `prepare_today_video` resolves the calendar slot first and loads its **CTA-free** canonical lesson. `scripts/auto-storyboard.mjs` selects the approved presentation from `content/visual-system.json#lessonPresentation` and the compatible creative packaging from `content/creative-formats.json`, before central CTA hydration. Exact voice cues are compiled only after Gemini import. Earlier eligible lessons retain the semantic pipeline above. Modified, rendered, approved and voice-prepared copies are never silently overwritten; the command reports an actionable conflict. For eligible new work, the normal workflow generates Gemini narration and word-timed captions through the API, then renders the full review MP4 package. Profile and package approval are still required before publication.

`npm run content:viral-plan -- --json` continues to be a **read-only** reporting and experiment-planning command. It reads `content/creative-formats.json`, existing future calendar episodes and the validated Zernio feedback snapshots; it does **not** modify episodes, scripts, voice, CTA, media or publication. The hook experiment ID/format already registered on an episode remains authoritative: no automatic hook migration is authorized. The 12-post pilot is a goal, not a second calendar or an instruction to invent dates. Integrate relevant shot/beat guidance into **new or unapproved** source drafts only after genuine teaching-source verification; preserve the single learning point, current hook controls and current central platform CTA. For evidence-based decisions require same-platform/level/duration actual 7d readbacks with verified post-to-episode-to-format attribution. Never use cumulative lifetime views to claim a winning format.

## 3. Generate and import speech

1. Read the current provider, model, voice and approval status from the selected language’s `voice-profile.json`. Check `modelDecisionRequired` first; it requires the exact owner model decision before any sample API call. While a profile is `pending-owner-approval`, generate only the sample episode named there; wait for the owner to approve that sample before using it for other episodes.
2. Run `npm run content:voice -- <episode-ID>` or the normal `content:make` workflow. It writes the exact narration and fingerprint, sends that same narration to Gemini TTS without a separate phonetic rewrite, converts the WAV response to MP3, and sends the MP3 to Gemini Transcribe for verbatim word timestamps with the selected explanation language and Simplified Chinese hints.
3. The generator compares the normalized word sequence against the complete narration. It imports MP3 and VTT automatically only when every word matches and all timestamps are valid. After three mismatched transcription attempts, only the designated pending sample may reuse a prior sample whose exact narration, Gemini voice/model and timestamp alignment all validate; both the rejected attempt and fallback provenance are retained in metadata. For other episodes, a mismatch keeps generated files and diagnostics under `review/<episode-id>/gemini-production/<timestamp>/` and blocks rendering. Diagnose the specific mismatch before retrying; never regenerate or replace an owner-approved audio file to work around transcription.
   - For TikTok's approved manual-DM variant, pass `--platform tiktok` to voice generation so its narration, audio and word cues stay in `review/<id>/tiktok/`; do not replace the existing root review episode or its exports.
4. If a mixed explanation-language/Mandarin full-audio pass translates or omits spoken Mandarin syllables, recover captions from the saved audio using the same Gemini Transcribe model and provider: (a) keep the normal full-audio pass with the locale from the selected language’s `voice-profile.json` and the Simplified Chinese hint; (b) isolate only the audible Mandarin spans and transcribe those clips with the Simplified Chinese hint, requesting verbatim word timestamps; (c) isolate spoken Latin acronyms such as “HSK AI” and transcribe those clips with the locale from the selected language’s `voice-profile.json`; (d) save the original pass responses and each source clip's start/end offsets beside the saved generation; (e) convert each clip timestamp back to the source timeline, merge annotations in time order with the explanation-language pass, and map Hanzi to the episode's written phonetic token only when the character and spoken syllable are verified. Do not estimate missing timestamps or write VTT unless the existing exact normalized-token check and timestamp validation both pass. Then resume with `npm run content:voice -- <episode-ID> --resume <timestamp-folder>`. Do not change the approved voice, provider or audio.
5. The importer verifies the narration fingerprint, cue granularity, cue bounds, eligible voice profile (approved profile or its designated pending sample) and publication state. It maps timed cues to scenes, records the generated audio in `public/generated/`, and removes trailing silence only after the final timed word. Record the complete natural video duration against `content/visual-system.json#duration` as guidance; the 45–55 second range is preferred, with no hard duration limit. Keep useful narration and the complete CTA, and never pad silence, stretch audio or truncate speech to reach a target.
6. Narration text and generated audio are sent to Google Gemini. Audio uploaded for transcription is deleted after the request; any deletion failure is written to the run metadata. Keep the API key only in local `.env.local`. Do not request routine file downloads or movement from the owner.
