# Content planning guide

The live production calendar is **`calendar.json`**. It owns dates, episode IDs, per-date topics, the timezone and scenario planning cadence. Do not mirror its rows or hard-code episode counts here.

For each scheduled episode, maintain one shared canonical lesson at `episodes/<episode-id>.json` and complete localized CTA-free versions under the content roots configured by `languages.json`. Keep IDs/dates/Chinese examples consistent and bind each translation to the current canonical raw JSON with `localization.sourceHash`. Missing or stale translations are production blockers for their language, never a reason to substitute original-language media. Apply the current global rules (`../AI_RULES.md`), active hook corrections (`HOOK_LAB.md` and `hook-lab.json`), and current CTA configuration (`cta-lab.json`).

A plan should specify one learner problem, source-checked examples, a topic-specific opening, all-language narration, `storytelling` context/selection for newly authored drafts and per-scene exact spoken `cueText` with meaning-linked `motionBeats`; use `GRAPHIC_SCENES.md` for original drawn objects/actions. The platform closing action comes only from the language's central CTA Lab **after** canonical CTA-free planning. Read `EDITING_SPEC.md` for the approved presentation and `EPISODE_SCHEMA.md` for required authored action plans before counting a new source draft as complete. Production and approval steps are in `WORKFLOW.md`.

For the owner-authorized daily future buffer replenishment, the agent may repair verified unapproved future CTA-free lessons and add new calendar dates + complete episode JSON **directly to `main` through the connected GitHub connector** when the buffer is below the target in `calendar.json`; no scenario PR is required. The exact scope and verification procedure are owned by `WORKFLOW.md` ("Automated scenario reserve — direct `main` delivery"). Use regular `planningWeekdays`, the optional consecutive-part exception in `seriesPolicy`, and target from `calendar.json`, and `scripts/scenario-buffer-plan.mjs` as a read-only date proposal. For a shared Instagram Reels/YouTube Shorts lesson, read `.agents/skills/ig-reel-planning/SKILL.md` to advise on the hook/storyboard; `hook-lab.json` remains authoritative. Date proposals alone are not written scripts. Count a future slot as complete only after the canonical Russian and **every** configured translated version exist, are source-hash aligned, and pass the current `visual-system.json#lessonPresentation` and cue-linked motion-plan checks. `content:buffer` now validates canonical plus all configured localized source drafts and reports missing/stale language-specific blockers. It remains a **source** audit: actual Gemini word timing, final MP4 and preview approval need separate production QA. Rendering must pass the existing voice/cue/review gates; the owner's approval of the exact final preview is mandatory **before publication**, not a blanket prohibition on preparing a review render. Do not rewrite old approved or published episodes.

If the owner modifies the schedule or a theme, edit `calendar.json` and the affected canonical episode in the same task. This guide must not become a second calendar.

## Typed weekly reserve

`calendar.json#weeklySchedule` owns the daily content mix for all default languages. Keep complete, localized CTA-free source scripts for the next `planningBuffer.targetFutureEpisodes` scheduled future dates (currently 4), across all content types: lesson, advertisement and both parts of a serial. These are scheduled calendar days, not four lessons; if an ad is due, use `promos/<id>.json` and its RU/TG locale versions as defined in `PROMO_WORKFLOW.md`, not a lesson placeholder. Use the typed near-slot adviser in `WORKFLOW.md`; ordinary lessons cannot replace ad/serial slots. Failed checks or missing evidence should be reported and retried at the next daily run, never used to disable the running Calendar Reserve task. Stable IDs and future evidence tests follow `feedback/CONTENT_TRACKING.md`.
